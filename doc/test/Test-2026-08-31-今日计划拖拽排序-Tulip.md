## 功能变更：今日计划条目支持拖拽排序

### 变更概要

在「今日计划」页面中，将计划条目（待完成项）设置成可以拖拽排序。用户拖动任意待完成条目到目标位置即可调整顺序，排序结果持久化保存；重启或切换页面后顺序保持不变。"全部 / 今天 / 明天 / 逾期"各标签下均可拖拽，跨日期的顺延项也能按展示顺序持久化。

### 修改文件清单

| 文件 | 变更类型 | 说明 |
|------|----------|------|
| `public/js/logic.js` | 修改 | 新增纯函数 `reorderPlansBySequence(plans, seq)`：按新的展示顺序重排各源日期的计划数组 |
| `public/js/pages/today.js` | 修改 | 待完成条目设为可拖拽，新增 dragover/dragleave/drop 事件处理，放下时调用 `reorderPlansBySequence` 持久化顺序 |
| `test/logic.test.js` | 修改 | 新增 6 个 `reorderPlansBySequence` 单元测试 |

### 功能说明

#### 交互方式

- 每个「待完成」条目可直接拖拽（`cursor: grab`），鼠标按住拖动到目标位置松开即可排序。
- 拖拽过程中目标行高亮提示（`.drop-target`）。
- 只有待完成项可拖动；已完成项固定展示在「已完成」分隔区之后，不参与排序。
- 排序后出现提示「已排序」，并按新顺序重新渲染。

#### 实现方式

- **`reorderPlansBySequence(plans, seq)`**：接收 `plans` 对象和按新展示顺序排列的 `seq`（每项为 `{ date, id }`，`date` 是条目真实存储的日期），对每个源日期数组重排，使其中各条目相对顺序与 `seq` 一致；已完成及其他未列出的项保持原相对顺序附在末尾。返回是否发生变更。
- **拖拽持久化**：放置时收集当前待完成行的展示顺序（含 `_src` 源日期），计算出目标插入位置后调用 `reorderPlansBySequence`，在 `mutate` 内写入 store，实现跨日期混合视图（"全部/逾期"）下的正确排序。

### 新增测试用例（6 个）

| # | 测试名称 | 测试内容 |
|---|----------|----------|
| 1 | 同一天内重排多个未完成项 | `['p1','p2','p3']` 将 p3 拖到最前 → `['p3','p1','p2']` |
| 2 | 已完成项保持原相对顺序附在末尾 | 重排待完成项后，已完成项 `['p3','p4']` 仍在数组末尾且相对顺序不变 |
| 3 | 跨日期（顺延项）也能按展示顺序持久化 | 今日项与昨日顺延项混合重排，各源日期数组均正确更新 |
| 4 | 未变化的顺序返回 `changed=false` 且数组不变 | 顺序未变时不产生任何写入 |
| 5 | seq 含未知 id 或非法项时安全跳过 | 不存在的 id 被忽略；缺 `date` 的项不参与排序，不报错 |
| 6 | 空 seq / 无对应日期 / plans 为空 均安全 | 边界输入返回 `false` 且不抛错 |
